# Terra II migration to pure game MVU

Proposal, 12 November 2026, against Terra II 5253bb2. Dungeon establishes the shared runner. Terra II adds the sound and asynchronous storage cases.

1. **Freeze a short seeded match transcript.** Cover buffered input during animation, a rule firing at its animation midpoint, a paused tick, and a return to an idle player turn. Compare board and resource state, queued actions, cue order, and save eligibility. Preserve the 40 ms game tick and the existing save format. [Game loop](../src/terra2.fpr) · [Save codec and idle predicate](../src/save.fpr)
2. **Route inputs and outputs through update.** Use key and wheel decoders and a tick subscription. Keep selection, action and AI functions small. Translate transient cue and transcript lists into ordered sound and log commands once per transition, preserving the current cue variation input. Emit screenshot and quit commands at their current gameplay boundaries. Model fields that the HUD actually displays can still be retained. [Actions](../src/actions.fpr) · [Input](../src/input.fpr)
3. **Load through tasks.** Init returns the title/loading model and requests profile replay and the latest saved game. Small pure decoders retain compatibility with existing profiles and snapshots. Distinguish absent data, corrupt data and unavailable storage. Offer Continue only after a valid snapshot loads. Allow no-disk play and guard against a late load overwriting a newly started game.
4. **Acknowledge saves explicitly.** Today flush issues appends, drops their results and clears the queue. Give each save batch an identity and retain its unacknowledged records in model state. Serialize writes in their existing order. On completion, acknowledge the confirmed prefix and preserve events added while the task was running. Keep a definitely failed suffix available for retry. For an uncertain append, reconcile with stored data or surface the uncertainty before retrying a profile event. Emit the saved announcement after confirmation. Retain the idle-turn snapshot and end-of-game tombstone semantics. [Current flush](../src/save.fpr)
5. **Move platform setup into the adapter.** Declare the 960 × 600 window, music and mesh assets in config. Compose the existing board and HUD as a pure layered element tree. Game.run owns Files, graphics, playback and shutdown. [Board scene](../src/scene.fpr) · [HUD](../src/ui.fpr)
6. **Accept the migration.** In a headless match, assert one sound for an attack across repeated renders and the same rule result at the animation midpoint. Inject failed, partial, stale and uncertain save completions. Check that new records survive and confirmed profile events are never blindly replayed. Reopen a pre-migration save and compare the resumed board, turn and counters. Run the existing GUI test and add a two-launch save/continue check using one temporary disk. [GUI harness](../tests/check.sol)

## First replaceable search: a tactical hint

Start with an optional hint for the selected unit. Submit a snapshot of relevant tactical state when selection or board legality changes. Score legal actions in deterministic order, advancing a fixed number of candidates per step. A new selection replaces the search. Clearing selection or leaving play cancels it. Accept a suggestion only when its revision still matches, and let the player decide whether to act. The visual clock does not invalidate it. Test rapid selection changes and a completion arriving after restart.

The existing greedy opponent builds its action queue at enemy turn start. A deeper opponent can later reuse the task interface with a fixed node budget and deterministic tie breaks. Keep a committed opponent turn pending until its matching plan arrives, then enqueue its actions once. [Planner](../src/ai.fpr) · [Turn start](../src/actions.fpr)
